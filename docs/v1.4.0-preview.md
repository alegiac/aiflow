# AIFlow 1.4.0 — Daily Workflow & Existing Project Adoption

This release contains **no Jira, MCP, or external tracker integration**. Existing local time tracking remains available.

## Daily workflow
```sh
aiflow day start
aiflow day start --json
aiflow day end --summary "API completed" --next "Integration tests"
```
Daily start resumes an open session and summarizes pending tasks. Daily end closes active local tracking, ends the session, and saves a local checkpoint. Repeated end calls are harmless.

## Adopt an existing project
```sh
cd /path/to/existing/project
aiflow adopt
aiflow adopt --conversation /path/to/export.md
aiflow adopt --conversation /path/to/export.md --apply
```
Preview does not modify project files. Apply initializes AIFlow and generates `.aiflow/adoption-review.json` and `.aiflow/adoption-review.md`. Git history, manifest dependencies, and selected transcript excerpts provide evidence for human review. No unverified statement is treated as an approved decision. Conversation access requires an explicit exported file; no private provider history is accessible automatically.

## Continuous Markdown specifications

```sh
aiflow epic create "Billing"
aiflow task create EPIC-001 "Invoice PDF"
aiflow specs sync
aiflow specs record architecture "Use PostgreSQL for persistence" --by user --evidence "Architecture review 2026-10-27"
aiflow specs record project "Billing is in scope" --by user --evidence "Scope approved in meeting"
```

Existing `epic create` and `task create` commands create dedicated Markdown documents in draft status and automatically refresh the project inventory. `specs sync` appends approved decisions to their corresponding Epic/Task Markdown and updates project inventory and current state. Day start/end invoke consolidation. Project and architecture specifications only receive substantive additions with explicit evidence and actor; AIFlow never fabricates design decisions.
